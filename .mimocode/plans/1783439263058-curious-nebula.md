# Plan: Оптимизация размера Zorro.json

## Анализ проблемы

Текущее состояние файла `Zorro.json` в WPF output (37.28 MB):
- `ReferenceHandler.Preserve` работает: 2.8M `$id` + 3.8M `$ref` записей
- **Но файл ВЫРОС** с 32.67 MB до 37.28 MB (+14%)
- Причина: overhead от `$id`/`$ref` записей (~15 байт каждая) перевешивает выгоду от дедупликации

### Почему `ReferenceHandler.Preserve` не помогает

1. **Container objects дедуплицируются** — все файлы из одного архива ссылаются на один Container
2. **Но millions of уникальных объектов** (файлы, SimpleFileInfo, ArchiveFileInfo) каждый получает `$id`
3. **Overhead**: 6.6M записей × ~15 байт = ~99 MB потенциального overhead
4. **`WriteIndented = true`** добавляет ещё больше whitespace

### Что реально уменьшит размер

| Оптимизация | Ожидаемый эффект |
|---|---|
| `WriteIndented = false` | **~30-40%** уменьшение (убирает отступы/переносы) |
| Убрать `ReferenceHandler.Preserve` | **~14%** уменьшение (убирает overhead `$id`/`$ref`) |
| **Итого** | **~40-50%** уменьшение (32 MB → ~16-20 MB) |

## Изменение

**Файл:** `BusinessLogic/SerializationHelpers.cs`

```csharp
public static JsonSerializerOptions CreateOptions()
{
    return new JsonSerializerOptions
    {
        Encoder = JavaScriptEncoder.Create(UnicodeRanges.All),
        WriteIndented = false,  // ← было true
        TypeInfoResolver = ArchiveJsonContext.Default
        // ReferenceHandler убран — overhead больше выгоды
    };
}
```
