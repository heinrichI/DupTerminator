# Implementation Plan

[Overview]
Исправить баг в режиме MD5 Container при котором когда два архива полностью идентичны по контрольной сумме - в результатах дополнительно отображаются все файлы внутри этих архивов как отдельные дубликаты.

Проблема заключается в том что после обнаружения полного совпадения контейнеров, записи про совпадения отдельных файлов внутри этих контейнеров остаются в результирующем списке и не фильтруются. Исправление заключается в добавлении логики удаления всех вложенных записей для контейнеров которые полностью идентичны.

[Types]
Изменения в типах не требуются. Используются существующие классы: ContainerPairKey, LocalContainerInfo, DuplicateContainer.

[Files]
Требуется модифицировать только один файл.

- **Изменяемый файл**: `BusinessLogic/SearcherMD5Container.cs`
  - Добавить логику фильтрации вложенных записей после прохода 2
  - Оставить логику работы неизменной для остальных случаев

[Functions]
Требуется добавить новую функцию и модифицировать существующий метод.

- **Новая функция**: `bool IsInsideContainers(ExtendedFileInfo file, ExtendedFileInfo container1, ExtendedFileInfo container2)`
  - Проверяет находится ли файл внутри одного из указанных контейнеров на любом уровне вложенности
  - Возвращает true если файл является потомком container1 или container2

- **Модифицируемый метод**: `StartAsync()` в строках после 220
  - После завершения второго прохода (строка 220) добавить новый проход по словарю containers
  - Найти все пары у которых установлен флаг `TheyThemselvesAreEqual = true`
  - Удалить из словаря все другие записи которые относятся к любым файлам внутри этих контейнеров

[Classes]
Изменения в классах не требуются. Все изменения будут внутри существующего класса `SearcherMD5Container`.

[Dependencies]
Новые зависимости не требуются.

[Testing]
Требуется добавить новый тест в существующий тестовый файл.

- **Тестовый файл**: `DupTerminator.Test/SearcherMD5ContainerTests.cs`
  - Создать тест кейс с двумя идентичными архивами
  - Проверить что в результате возвращается только одна запись (пары архивов)
  - Проверить что записи про отдельные файлы внутри архивов отсутствуют в результате

[Implementation Order]
Порядок реализации изменений:

1.  Добавить вспомогательный метод `IsInsideContainers` в класс SearcherMD5Container
2.  После строки 220 в методе StartAsync добавить проход по всем парам с флагом TheyThemselvesAreEqual
3.  Для каждой такой пары удалить из словаря containers все записи где любой из файлов находится внутри этих контейнеров
4.  Оставить существующую логику фильтрации и сортировки без изменений
5.  Добавить отладочное логирование количества удаленных записей
6.  Создать и запустить юнит тест для проверки исправления
